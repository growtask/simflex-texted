## Безопасность (прочитайте обязательно)

Принцип: **в редакторе и на сайте не выполняется ничей код из содержимого** — ни при правке, ни при выводе.
Редактор работает в браузере, а значит **клиентской очистке доверять нельзя**: человек с доступом в админку (или тот, кто перехватил его сессию)
может отправить на сервер любой HTML мимо редактора. Защита сайта — очистка на сервере и несколько настроек сервера.

1. **Очищайте HTML на сервере перед сохранением и перед выводом.**

   ```php
   $ted = Config::load();
   $clean = $ted->save($_POST['content'], $preset, $canEdit);   // сохранение: очистка по набору поля, без права — AccessDenied
   echo $ted->clean($page['content']);                          // вывод на сайте
   // без ted.config.php: Sanitizer::clean($html) (src/Sanitizer.php)
   ```

   Исключение — `Simflex\Texted\Exception\AccessDenied`: поймайте его и ответьте 403. Аргументы `Sanitizer::clean` и другие методы — [PHP-классы](install.md#php-классы).

   - **Белый список** тегов и атрибутов один в браузере (`resources/js/core/allowlist.js`) и на сервере (`src/Sanitizer.php`), тест сверяет их. Всё, что сохраняет редактор (все блоки), сервер оставляет без изменений.
   - **Убираются:** `script`, `style` (и тег, и атрибут), `on*`, `srcdoc`, `formaction`, `xlink:href`, формы и поля, `object`, `embed`, SVG, MathML, `link`, `meta`, `base`.
   - **Классы и id:** классы — только `ted-*`; `id` — латиница, цифры, `_` и `-`, с буквы, до 64 знаков.
   - **Проверки:** 123 вектора XSS (`tests/security-vectors.json`) — одни и те же в браузере и на PHP. Результат идемпотентен.
   - **Своя CMS на другом языке:** перенесите те же правила.
2. **Ссылки и адреса — одно правило** (`resources/js/core/urls.js` = `Sanitizer::urlOk`, общие примеры `tests/security/url-vectors.json`):
   - **можно:** `https:`, `http:`; в ссылках ещё `mailto:` и `tel:`; адреса без схемы — `/путь`, `#якорь`, `?запрос`, `страница.html`, `../папка/`, `//сайт/путь`;
   - **в картинке** ещё растровая `data:image` (PNG, JPEG, GIF, WebP, AVIF, BMP) — так вставлены картинки во многих старых статьях;
   - **нельзя:** `javascript:`, `vbscript:`, `data:` в ссылках и любой SVG, `file:`, `blob:`, `about:` и все прочие схемы. Это проверяется и в замаскированном виде: сущности `&#106;`, `&colon;`, табуляция и перевод строки внутри схемы, невидимые знаки, `%6A…`, любой регистр.

   Правило одно для ссылок, картинок, видео, аудио, фрейма, карточки, товара и кнопки.
3. **iFrame:** блок «iFrame» принимает любой `https`-адрес (или только сайты из `ted.config.php` → `iframe.hosts`); в старом HTML — только видеоплощадки. Всегда `sandbox`, `referrerpolicy="strict-origin-when-cross-origin"`, без `srcdoc`.
4. **Старый «сырой» HTML** (таблицы, картинки, свои вставки из прежнего редактора) показывается нередактируемым блоком. Сделать такой блок в редакторе нельзя: в меню его нет.
   - **По умолчанию** (`rawHtml: 'strict'`) он чистится тем же белым списком, что на сервере: в редакторе видно ровно то, что сохранится и попадёт на сайт.
   - **`rawHtml: 'trusted'`** оставляет формы, `object`, `svg` — только для полностью доверенных авторов; сервер всё равно очистит.
5. **Папка файлов (`uf/` или та, что в `ted.config.php`) — только данные.** Держите её вне папки пакета.
   - **Apache:** скопируйте `resources/uf.htaccess` в неё как `.htaccess`. Он запрещает выполнение скриптов и листинг, отключает угадывание типа (`nosniff`), ставит CSP `sandbox`, и документы скачиваются, а не открываются.
   - **nginx:**

     ```nginx
     location /uf/ {
         location ~* \.(php\d?|phtml|phar|pl|py|cgi|sh|asp|aspx|jsp)$ { return 403; }
         add_header X-Content-Type-Options nosniff always;
         add_header Content-Security-Policy "default-src 'none'; style-src 'unsafe-inline'; sandbox" always;
         location ~* \.(pdf|zip|docx|xlsx)$ { add_header Content-Disposition attachment always; add_header X-Content-Type-Options nosniff always; }
         autoindex off;
     }
     ```
6. **Загрузка:**
   - **Права:** только за авторизацией CMS и CSRF-токеном. `$ted->respondToUpload($pagePath, $preset, $canEdit)` проверяет право на правку; вход и CSRF проверяет CMS до вызова. Публичный путь страницы берите из записи CMS, а не из запроса.
   - **Тип файла:** определяется по содержимому, а не по расширению. SVG, HTML и скрипты не принимаются.
   - **Картинки:** JPEG, PNG и WebP пересобираются в WebP — метаданные и «двойные» файлы пропадают. GIF хранится как есть (анимация), поэтому GIF со встроенным HTML, скриптом или PHP отклоняется.
   - **Имена файлов** сервер делает сам: латиница по названию, расширение — по типу.
7. **Лимит частоты** (`ted.config.php` → `rate`): по умолчанию 60 загрузок и 20 запросов сервера наружу (карточка, картинка по ссылке) в минуту на пользователя. Сверх лимита — ответ 429. Карточку отдавайте через `$ted->respondToOpenGraph()`.
8. **Запросы сервера наружу** (карточка по ссылке, картинка по ссылке):
   - только `http(s)`, порты 80 и 443, без логина в адресе;
   - все адреса сайта должны быть публичными — внутренняя сеть, `localhost`, служебные диапазоны и IPv4 внутри IPv6 отклоняются;
   - запрос идёт на тот же проверенный IP, повторного обращения к DNS нет: подменить адрес между проверкой и запросом нельзя;
   - сертификат проверяется по имени сайта;
   - не больше 3 перенаправлений, каждое проверяется заново;
   - время — 6 с на ответ и 15 с на всё, размер ограничен.
9. **CSP на сайте.** Содержимое texted и `content.js` работают со строгой политикой без встроенных скриптов и стилей. Это проверяет тест: страница со всеми блоками, нарушений 0. Рекомендуем:

   ```
   Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data: https:; media-src 'self' https:; frame-src https:; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'
   ```

   - **`frame-src`:** если блок «iFrame» ограничен списком сайтов, перечислите их здесь вместо `https:`.
   - **`img-src` и `media-src`:** если файлы лежат на CDN, добавьте его адрес.
10. **Импорт и вставка.** Вставка из буфера, импорт списка блоков (`Ted.fromBlocks`) и загрузка документа идут через ту же очистку. Текст полей JSON всегда остаётся текстом.
11. **Предпросмотр** рисуется в `iframe` с `sandbox="allow-same-origin"`: скрипты из содержимого в нём не выполняются.
12. Ссылки, которые открываются в новой вкладке, получают `rel="noopener"` (сервер — `noopener noreferrer`).
