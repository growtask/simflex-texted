# Автотесты Ted

Тесты на чистом JS: без Node.js, без npm, без внешних библиотек. Раннер (`harness.js`) — около 60 строк. Запускаются в браузере, на исходниках из `src/`.

## Запуск

1. Собрать стили: `pwsh -File tools/build.ps1` (тесты берут `dist/ted.css`).
2. Поднять сервер: `pwsh -File tools/serve.ps1 -Port 8140`.
3. Открыть `http://localhost:8140/tests/index.html`.

Страница сама прогонит все проверки (около 1–2 минут: часть проверок ждёт таймеры и анимации, а демо-страницы грузятся в iframe). В заголовке вкладки итог: `✓ Все тесты прошли: 339` или `✗ Не прошло N из M`. Упавшие проверки показаны красным с сообщением.

| Параметр адреса | Что делает |
|-----------------|------------|
| `?q=якорь` | прогнать и показать только тесты, в названии которых есть слово |
| `?keep` | не убирать редакторы после прогона (посмотреть, что получилось) |
| `?only=тостеры` | выполнить только тесты, в названии которых есть слово (быстрый запуск одной группы; `?q` лишь фильтрует показ) |

Для автоматического запуска (скрипт, CI с браузером): дождаться `window.__tedTests` — объект `{ total, failed: [{ name, error }] }`.

## Как писать тест

```js
import { group, test, eq, ok, wait } from './harness.js';

group('Моя область', () => {
  test('что проверяем', async () => {
    eq(1 + 1, 2);                 // строгое равенство, понятное сообщение при ошибке
    ok(условие, 'что не так');    // условие истинно
    await wait(400);              // подождать таймер редактора
  });
});
```

Помощники: `eq`, `deepEq`, `ok`, `wait`, `vis` (неразрывные пробелы показывает как «·»). В `helpers.js` — `make(html, options, { width, theme })` (новый редактор нужной ширины и темы), `select(ed, блок, от, до)`, `selectText(ed, 'слово')`, `typeText('...')` (настоящий ввод через `execCommand`), `pressEnter(ed)`, `pop(ed)` (окно этого редактора), `html(ed)`, `tagOf(ed, i)`.

Новый файл: `что-то.test.js` и строка `import './что-то.test.js';` в `tests/index.html`.

## Правила, о которые легко споткнуться

- **Окна редактора ищите через `pop(ed)`**, а не через `document.querySelector('.ted-ui-pop')`: окна прошлых тестов могут остаться в странице. `make()` их убирает, но привычка спасает от ложных ошибок.
- **`getInnerHTML()` не отдаёт пустые блоки.** Пустой заголовок после «# » проверяйте через DOM (`tagOf(ed)`), а не через HTML.
- **Таймеры.** `onChange` и черновик срабатывают через 250 мс после правки: ждите 400 мс.
- **`onSave` вызывается, только если текст изменился** (при сохранении без правок редактор просто уходит в просмотр).
- **Настройки браузера.** Выключенные категории ✨ запоминаются в `localStorage` (`ted-typograf-off`). `make()` сбрасывает ключ, но в своём тесте не полагайтесь на его состояние.
- **Типографика уже набранного текста.** Строка вроде «Всё хорошо» не считается «уже в порядке»: после слова до трёх букв стоит неразрывный пробел. Для проверки «ничего не менять» берите текст с `&nbsp;`.

## Размеры и темы

Тесты `sizes.test.js` создают редактор в обёртке нужной ширины (`make(html, options, { width: 414, theme: 'dark' })`): колонка, сетка плиток и мобильная шапка меню зависят от ширины контейнера (`@container ted`), а не окна браузера, поэтому проверяются в одном окне. Ожидаемые значения: колонка 700 / 628 / 480 / 382, плиток в ряд 3 / 3 / 2 / 2. Размеры слоя анимации (масштаб при появлении окна) измеряйте через `offsetWidth` / `offsetHeight`, а не `getBoundingClientRect`.

## Smoke-тест сборки

`tests/dist.html` загружает собранные `dist/ted.js` и `dist/ted.css` обычными `<script>` / `<link>` (как на сайте) и проверяет: глобальный `Ted` и его API, создание редактора и сохранение HTML с подсветкой кода, очистку опасного, оформление блоков без JS, `destroy`. `pwsh -File tools/test.ps1` гоняет эту страницу после основной (с `-Only` — только основную). Такой тест ловит ошибки, которые видны только в склеенном файле (повтор имён, синтаксис после склейки).

## Обход всех блоков (визуальный)

`tests/walkthrough.html` — живой редактор: каждый блок добавлен через меню «Все блоки», наполнен (набор текста, Enter, Tab, Ctrl+Enter) и пройден доступными кнопками панели (жирный, курсив, подчёркнутый, зачёркнутый, код, ссылка, якорь, выравнивание, цветной фон, стиль текста, ✨). Перед каждым результатом — подпись `h6`. Автопроверки после каждого шага: нет горизонтальной прокрутки, нет блоков за колонкой, в сохранённом HTML нет служебных атрибутов и нулевых пробелов, повторная очистка не меняет HTML, нет ошибок скрипта. Справа внизу — сводка. `?dark` — тёмная тема. Ширину проверяют окном браузера (1000 / 860 / 768 / 414): медиазапросы содержимого зависят от окна, поэтому автотесты в окне 1200 их не проверяют — только эта страница. Адрес: `http://localhost:8140/tests/walkthrough.html` (через `tools/serve.ps1`).
## Прямая загрузка по HTTP

На Windows с PHP 8.4+ (`gd` с WebP, `fileinfo`) запустите `pwsh -File ted/tests/upload.test.ps1` из корня проекта. Можно передать путь через `-Php`. Скрипт поднимает локальный сервер, проверяет PNG → WebP, сохранение под публичным путём и удаление после сохранения, использует временный каталог.

Для сквозной проверки через браузер запустите демо с PHP по инструкции модуля и откройте `/tests/index.html?php-upload&only=Медиа%20HTTP` на том же сервере.

## Быстрые и полные прогоны

`pwsh -File tools/test.ps1` — быстрый: логика (`?fast` на `tests/index.html`: матрица «ширина × тема» только для 1000 px, светлая) и smoke `dist`. `pwsh -File tools/test.ps1 -Full` — полный: вся матрица, обход блоков в 8 окнах, `tools/check-builds.ps1` (сборки на PHP и PowerShell одинаковы), `tests/upload.test.ps1` (PHP-загрузка). Полный запускают по завершении этапа или по запросу. `tools/find-php.ps1` ищет `php.exe` в PATH и в обычных местах установки.
